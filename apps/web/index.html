Translation that doesn't wait for the sentence to end.

nyv streams at every hop. Speech is recognised while it is spoken, translated as words are committed, and voiced while the translation is still being written. Each stage overlaps the next.

  1. 01

    Listen

    Call audio is captured in the browser. On-device voice activity detection marks phrase ends in milliseconds.

  2. 02

    Recognise

    Streaming speech recognition commits words as soon as they are stable, not when the speaker pauses.

  3. 03

    Translate

    A low-latency LLM translates with the conversation as context, so names, numbers and questions survive the trip.

  4. 04

    Speak

    Streaming text-to-speech starts voicing the first words of the translation before the last words exist.

  5. 05

    Stay in sync

    The original speaker is ducked, not muted. If translation falls behind, playback speeds up imperceptibly to catch up.

Built like infrastructure.

Latency is measured, not promised. Every segment carries per-hop timestamps from phrase end to the speaker, and a replay benchmark gates every change to the pipeline.

Read the source on GitHub
  • Streaming everywhere Binary PCM over one WebSocket; ASR, MT and TTS all stream-input.
  • Speculative commit LocalAgreement on partial transcripts; translation starts before the final.
  • Catch-up playback Pitch-preserving time stretch keeps you within a sentence of the speaker.
  • Pre-warmed voices TTS sockets are opened before they are needed; no handshake on the critical path.
  • Open core MIT-licensed monorepo. Swap vendors behind one interface.
